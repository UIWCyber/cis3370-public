Group the Rows Without Looking at the Labels

  • An everyday version. Sort a pile of laundry into piles that belong together, without being told what the categories are. You can still say "this pile is mostly dark" afterwards.
DefinitionClustering, and k-means. Ask for k groups; the method puts every row in the group whose centre it is nearest, moves the centres, and repeats. It never sees a label.
  1. 1The order matters. Group the training rows with no labels. Then look up each group's attack share from the training labels, which is the one place a label is used. Then send a test row to its nearest group and flag it if that group is mostly attacks.
  2. 2The groups themselves owe nothing to the labels, so a kind of attack nobody labelled can still land in one.

15

Decide: a Second Channel, Not a Replacement

  1. 1Do not replace the supervised model with it. It catches a sixth of the attacks and misses more unseen types than the tree does.
  2. 2Do run it beside the model as a quiet second channel: 4 false alarms across the whole test file means an alert from it can be acted on without triage.
  3. 3Write the rule down: a row in a group whose training attack share is at least 0.90 is flagged, whatever the model said. Re-measure the group shares whenever you retrain.
Why it mattersThe idea that sounded best is not the one that worked, and the thing it turned out to be good at is not what it was proposed for. Report both, because the next team will otherwise propose it again for the wrong reason.

The Measurement

How you askRows per second
one row at a timeabout 2,500
the whole file at onceabout 6.3 million
Why it mattersThe work per row is tiny and the cost is in making the call. That gap is per-call overhead, and it decides whether a detector keeps up with a busy link.
  1. 1Score in batches whenever the data arrives in batches, which is most of the time.
  2. 2Score one at a time only when the answer is needed before the next packet, and then measure it.
  3. 32,500 per second is not slow. It is just not 6.3 million.

What an Agent Actually Is

  1. 1A language model, in a loop, with tools: read a file, run a command, write a file.
  2. 2The loop is the difference. It sees the output of what it ran and decides what to do next.
  3. 3Everything it did this term was one of those three tools, plus your judgement about whether the answer was right.
DefinitionAgent. A model that can act, observe the result of acting, and act again, until it decides it is done or you stop it.
CIS 3370 Intrusion Detection Systems
21

What It May Do, and What It Must Ask

  1. 1May: read the files you pointed it at, run analysis, write into your working folder.
  2. 2Must ask: anything outside that folder, anything that sends data somewhere, anything that deletes.
  3. 3Never: credentials, other people's machines, or the university network.
Watch outAn agent that can run commands can run destructive ones. The habit that protects you is the same one this course teaches about models: read what it proposes before you approve it, and keep the folder it works in small.
CIS 3370 Intrusion Detection Systems
22

Judging an Agent's Work

  1. 1Did it run what it said it ran? The report has the commands, so you can check.
  2. 2Did the numbers come from the data, or from the model's memory of a similar dataset?
  3. 3Would you be able to reproduce the result without it?
Why it mattersThese are the same questions you ask of a paper in the reproduction sessions. An agent is a collaborator whose work you check, not an oracle.
