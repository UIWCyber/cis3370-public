A Model Does Not Accept a Table

Three Things a Matrix Has To Be

  1. 1Numeric. Every column. A model cannot multiply the word http by a weight.
  2. 2Complete. No missing values, or a declared decision about what to put there.
  3. 3Comparable. A column that runs to millions should not outvote one that runs to ten.
NoteNSL-KDD is unusually kind here: no missing values at all. Say that out loud, because the next dataset will not be, and you should notice the difference rather than assume it.

Which Turns 41 Columns Into 122

  1. 138 columns were already numbers and stay as they are.
  2. 23 text columns become 3 plus 70 plus 11, which is 84 new columns.
  3. 338 plus 84 is 122 columns, from 41. service is two thirds of the growth on its own.
Why it mattersWidth is not free. Every column is a weight to learn, and a column that is 1 in eleven rows out of 125,973 gives a model almost nothing to learn from.

The Category You Have Never Seen

  • Encode with training categories, and a value that appears only at test time has nowhere to go.
  1. 1In this dataset you are lucky: every service in the test file also occurs in training.
  2. 2Six services occur only in training, which is harmless: their columns are simply all zero at test time.
  3. 3On your own data you will not be lucky, so decide now: an other bucket, or drop the row, or fail loudly.
Watch outThe wrong answer is to encode training and test separately. You get two matrices with different columns in a different order, and everything after that is quietly meaningless.

Two Steps, in This Order

  1. 1log1p first, because the byte columns run from 0 to hundreds of millions and are full of zeros.
  2. 2Standardize second, so every column is measured in standard deviations rather than in bytes.
  3. 3Fit the standardizer on training data only. Apply it to both.
DefinitionFit. Measuring the mean and the spread. Apply. Subtracting and dividing. The rule is that fitting sees only training data; applying may touch anything.

The Rule as a Tree

  1. 1Are you computing a number from the data, such as a mean, a scale, a category list, a vocabulary?
  2. 2Yes: compute it on training data only, then apply it everywhere.
  3. 3No, it is a fixed transformation such as log1p: apply it anywhere, it learns nothing.
  4. 4Unsure? Ask whether the transformation would change if you deleted the test set. If yes, it learns.
TipThis one question, would it change if the test set disappeared, catches almost every leak a student writes.

What "Good Accuracy" Is Worth Here

  • A model that always answers normal scores 53.5 percent on training and 43.1 percent on test.
  • It catches nothing, ever, and it would beat a careless first attempt.
Watch outAny accuracy number below about 54 percent on this training set is worse than answering the same thing every time. Accuracy is the metric that hides this, which is why the evaluation session exists.

Three Honest Answers to Imbalance

  1. 1Weight it. Tell the model a U2R row matters more. Under a balanced scheme, about 485 times more.
  2. 2Resample it. Duplicate or synthesise U2R rows until the classes match. That is 52 rows becoming 67,343, a factor of 1,295.
  3. 3Report per class. Change nothing about training, and refuse to publish a single accuracy number.
Why it mattersThese are not ranked. They fail differently: weighting distorts the loss, resampling invents data, and reporting per class leaves the model exactly as weak as it was but stops you lying about it.
CIS 3370 Intrusion Detection Systems
16

Which One, and When

  1. 1Choose weighting when the model accepts weights and you want one model that treats rare rows seriously.
  2. 2Choose resampling when the algorithm has no weights, and say in writing that you did it.
  3. 3Choose per-class reporting always, on top of whichever other one you picked.
TipDuplicating a row 1,295 times does not add information. It adds confidence about information you already had, which is how a model ends up certain and wrong.
