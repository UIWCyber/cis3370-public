What Just Happened, in Three Steps

  1. 1%{SYSLOGTIMESTAMP:timestamp} matched the front of the line and named what it matched.
  2. 2%{IP:source.ip} matched the address and put it under source, not under ip_addr or src.
  3. 3Everything the pattern did not name was thrown away, which is a decision, not an accident.
DefinitionGrok. A set of named regular expressions. %{PATTERN:field.name} means match this shape and store it under this name.

8

Dissect Is Grok Without the Regular Expressions

  • When the line really is fixed, %{} positions are faster and easier to read than a pattern.
  1. 1Grok backtracks. Dissect walks the line once and cannot.
  2. 2Dissect cannot say "a number here". It can only say "the next thing, up to this separator".
  3. 3Rule of thumb: fixed shape, use dissect. Variable shape, use grok. Both, use dissect first and grok the remainder.
Watch outA grok pattern that can match many ways is slow on volume, and it fails at the worst time: when a log line changes shape after an upgrade.

A Pipeline That Says Success and Does Nothing

  • The most expensive kind of bug is the one that reports zero failures.
CIS 3370 Intrusion Detection Systems
11

The Story, Exactly As It Happened

  1. 1An ingest pipeline renamed id.orig_h to source.ip, for 6,435 documents.
  2. 2It reported 6,435 created and zero failures.
  3. 3Not one field had been renamed. Every document still had its original key.
Why it mattersIn a pipeline, id.orig_h means the field orig_h inside the object id. Zeek's JSON has no object called id: it has one literal key whose name contains a dot. The processor looked for something that was not there, was told to ignore missing fields, and did so, 6,435 times.
CIS 3370 Intrusion Detection Systems
12

The Fix, and the Lesson

  • dot_expander turns the literal key id.orig_h into a real object id with a field orig_h. Then rename works.
Order matters: expand, then rename
$ dot_expander field: "id.orig_h"
$ rename field: "id.orig_h" target_field: "source.ip"
TipNever accept "no failures" as evidence that a pipeline worked. Read one document out of the destination and look at it. That check takes ten seconds and it is the only one that is honest.

What a Schema Does Not Fix

  • The join is still 83 percent. Naming was never the reason for the missing 17.
  1. 1Those flows began before the capture window opened. No field name recovers a packet nobody kept.
  2. 2A schema makes the question expressible. It does not make the data complete.
  3. 3Say which of the two you have, every time, or you will report a gap as a finding.
Watch outThis is the honest version of the sales pitch. A common schema removes translation work, and it does not improve your data.

18

Names Are a Decision, So Decide Once

  1. 1Pick the schema before you index, not after: renaming a field means rebuilding the index.
  2. 2Write the mapping down where the next person will find it, which is the pipeline.
  3. 3When a tool has no equivalent field, leave it absent rather than inventing a value.
NoteThe last one matters more than it sounds. A field that is sometimes missing is a question. A field that is sometimes zero because someone filled in a blank is a wrong answer that nobody will catch.
