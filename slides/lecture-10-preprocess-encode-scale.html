Learning Objectives

By the end of this session you will be able to:

A Model Does Not Accept a Table

  • It accepts a matrix: all numbers, no gaps, columns whose sizes are comparable. Everything in this session is the work of getting from one to the other without cheating.

Three Things a Matrix Has To Be

  1. 1Numeric. Every column. A model multiplies each column by a weight and adds; it cannot multiply the word http by anything.
  2. 2Complete. No missing values, or a declared decision about what to put there.
  3. 3Comparable. A column that runs to millions should not outvote one that runs to ten.
NoteKDDTrain+ and KDDTest+ have zero missing values, measured: 0 in 125,973 rows and 0 in 22,544. Say that out loud, because the next dataset will not be so kind, and you should notice the difference rather than assume it.

Decide: a Rule for the Rare Columns

  1. 1Keep a value's column when the value appears in at least 100 training rows.
  2. 2Below 100, the value goes into one rare column per original column, so its rows still say "something uncommon happened here".
  3. 3On this file: 17 columns fold into 2 rare columns, and the matrix is 107 columns wide instead of 122.
TipThe threshold is 100 because a weight learned from fewer rows than that is a guess. Write the number down; a reviewer can argue with 100, but not with "a few".

The Category You Have Never Seen

  • Encode with training categories, and a value that appears only at test time has nowhere to go.
  1. 1Measured: six services occur only in training (aol, harvest, http_2784, http_8001, red_i, urh_i) and none occur only in test. Their columns are simply all zero at test time.
  2. 2On your own data you will not be lucky. The rare column is where an unseen value goes, so decide that now rather than crash later.
Watch outThe wrong answer is to encode training and test separately. You get two matrices with different columns in a different order, and everything after that is quietly meaningless.

Decide: Which Columns Get the Log

  1. 1Rule: a column whose largest value is more than 1,000 times its average gets log1p first. Then every number column is standardized, with the average and the spread taken from training data only.
  2. 2On this file the rule says yes to src_bytes (30,285), dst_bytes (66,228) and num_compromised (26,782), and no to duration (149), srv_count (18) and count (6).
  3. 3num_compromised is the one a person would have skipped: 99 percent zeros, average 0.3, largest 7,479. The rule caught it because it looked at the number, not the name.
TipTwo columns on the same slide that the rule sorts differently is the whole point: src_bytes and count are both counts of something, and only one of them needs the log.

Decide: the One Question That Catches a Leak

  1. 1Are you computing a number from the data, such as an average, a spread, a category list, a vocabulary? Yes: compute it on training data only, then apply it everywhere.
  2. 2No, it is fixed arithmetic such as log1p: apply it anywhere, it learns nothing.
  3. 3Unsure? Ask whether the transformation would change if you deleted the test set. If yes, it learns, and it fits on training only.
TipThis one question, would it change if the test set disappeared, catches almost every leak a student writes.

The Smoke Alarm That Never Rings

  • An everyday version. In a building where a fire happens one day in ten thousand, an alarm that never rings is right 99.99 percent of the time and useless on the one day that matters.
DefinitionClass imbalance. The classes the model must tell apart are present in very different amounts, so the common one can be guessed and the rare one can be ignored while the score stays high.

Three Honest Answers to Imbalance

  1. 1Weight it. Tell the model a U2R row matters more. A balanced scheme gives each family the same total weight: 125,973 divided by 5 families divided by that family's rows. Normal 0.37, DoS 0.55, Probe 2.16, R2L 25, U2R 485.
  2. 2Resample it. Duplicate or synthesise rows until the families match: Probe 6 copies of each row, R2L 68, U2R 1,295. That is 52 rows becoming 67,343.
  3. 3Report per class. Change nothing about training, and refuse to publish a single accuracy number.
Why it mattersThese are not ranked. They fail differently: weighting distorts the loss, resampling invents data, and reporting per class leaves the model exactly as weak as it was but stops you lying about it.
CIS 3370 Intrusion Detection Systems
36

Decide: Which One, and When

  1. 1Choose weighting when the model accepts weights, which every model in Lecture 11 does, and you want one model that treats rare rows seriously.
  2. 2Choose resampling only when the algorithm has no weights, and say in writing that you did it.
  3. 3Choose per-class reporting always, on top of whichever other one you picked.
TipDuplicating a row 1,295 times does not add information. It adds confidence about information you already had, which is how a model ends up certain and wrong.
