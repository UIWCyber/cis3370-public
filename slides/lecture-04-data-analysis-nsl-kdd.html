Build the Family Column Yourself

  • The file gives you the attack name. It does not group them. That grouping is yours to make.
FAMILY = {"neptune": "DoS", "satan": "Probe", "guess_passwd": "R2L",
          "buffer_overflow": "U2R", ...}          # 22 names in training

for df in (train, test):
    df["Family"] = df["Class"].apply(
        lambda c: "Normal" if c == "normal" else FAMILY.get(c, "UNKNOWN"))

print(train["Family"].value_counts())
  • Four families: DoS, Probe, R2L, U2R. Normal traffic is its own label.
Watch outCheck for UNKNOWN before you trust the grouping. An attack name you did not map is a silent hole in every count that follows.

describe() and Its Blind Spot

train.describe().T[["mean", "50%", "max"]]
  • Only numeric columns appear, so text columns silently vanish from the summary.
  • The mean of a skewed column is not a typical value.
  • For Src_Bytes, mean is about 45,567 while the median is 44.
Why it mattersThe mean is dragged by a handful of enormous connections. Report the median for skewed data, and always look at the maximum.

  • Two columns can share a mean and look nothing alike. Plot before you conclude.

One Correction to the Reading

  • The blog groups interval under qualitative data. That is wrong.

  • Qualitative is nominal and ordinal. Quantitative is interval and ratio.
  • Use the reading for the examples, use this slide for the classification.

Discrete and Continuous Is a Different Question

  • Nominal, ordinal, interval, ratio describe what the values mean.
  • Discrete and continuous describe what values are possible.
  • Count is ratio and discrete: whole connections, never 2.5 of them.
  • Duration is ratio and continuous: any value in a range.
DefinitionDiscrete means countable in whole units. Continuous means you can always divide the interval further, at least in principle.

IID in Plain Words

DefinitionIndependent means one row tells you nothing about the next. Identically distributed means every row is drawn from the same underlying process.
  • Rolling one fair die repeatedly: independent, and identically distributed.
  • Dealing cards without replacement: identically distributed, but not independent.
  • Rolling a fair die, then switching to a loaded one: independent, but not identically distributed.
CIS 3370 Intrusion Detection Systems
26

Where Independence Breaks

  • Several rows describe the same session, so they rise and fall together.
  • Rows are ordered in time and neighbours look alike.
  • Rows are grouped: many rows per host, per user, per experiment.
  • Duplicate or near-duplicate rows appear in both training and test.
Why it mattersIf related rows land on both sides of a split, the model is tested on something it has effectively already seen. The score goes up, real performance does not.
CIS 3370 Intrusion Detection Systems
27

Where Identical Distribution Breaks

  • The training set and the test set are collected under different conditions.
  • The mix of classes changes between the two.
  • New categories appear later that did not exist earlier.
  • The world changes after the data was collected. This one is guaranteed in security.

How To Check, With Code

  1. 1Compare class shares: train["Family"].value_counts(normalize=True) against the same on test.
  2. 2Look for repeats: train.duplicated().sum().
  3. 3Compare category sets: set(test["Service"]) - set(train["Service"]).
  4. 4Ask where the rows came from, and whether any group spans both splits.

Fixing Scale Without Losing Rows

import numpy as np
for c in ["Src_Bytes", "Dst_Bytes", "Duration"]:
    train[c + "_log"] = np.log1p(train[c])
    test[c + "_log"]  = np.log1p(test[c])
  • Tools: log1p handles zeros, since log(0) is undefined and these columns are full of zeros.
  • Solution: transform, then standardize using statistics fitted on training only.
Watch outFitting a scaler on the combined train and test data leaks test information into training. The score improves and the model gets worse in production.

How To Present What You Found

  1. 1State the question, then the measurement, then the number. In that order.

  3. 3Name the consequence for the model, not just the statistic.
  4. 4Say what you changed and what you deliberately did not.
